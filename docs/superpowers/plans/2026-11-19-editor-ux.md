# Easier editor on phone and PC: plan

Roadmap item 2 (`docs/superpowers/plans/2026-11-18-roadmap.md`). Research:
`docs/superpowers/research/2026-11-18-editor-ux.md`. Owner's picks (2026-11-18, from mockups):
**phone B** (the bottom bar swaps to the selected design's actions) and **PC A** (a bar floats
above the selected design).

Owner's words: "like Photoshop or Canva ... if I want to duplicate, I want to delete, I should not
scroll back down ... for the phone there are some functions and buttons that don't show ... make
it usable and easy for all users."

## Goals

1. **PC: floating action bar** above the selected design (below it when there is no room above,
   never off screen), hidden while dragging, resizing or rotating, back on release. One design:
   Duplicate, Delete, Lock/Unlock, Rotate 90°, Flip, More. Several: Duplicate, Delete, Lock all,
   Align, More. "More" opens a small menu: flip vertically, bring forward / send backward / to
   front / to back, Add copies, Move onto the sheet / a sheet (when flagged), Open the inspector.
   Icons from the app's own set with tooltips and short labels; keyboard reachable; Escape closes
   the menu.
2. **Phone (≤ 820 px): one screen, no page scroll.** A `100dvh` app shell: top bar (logo, film
   metres, Undo, Redo, Export), the canvas filling the middle, a bottom bar at thumb height.
   - Nothing selected: **Add**, **Designs** (the list), **Arrange**, **Sheet** (sheet settings),
     **More** (New, Open, Save, Zoom in/out/Fit, Background, Grid, About).
   - A design selected: the bar swaps to **Duplicate**, **Delete**, **Lock**, **Rotate**, **Size**
     (size, angle, name, warnings), **More** (flip, layer order, copies, align), and a close
     (deselect) button.
   - Designs, Sheet, Size and More open as **bottom sheets** (non-blocking, drag handle, about
     half height at most, the selected design stays visible; swipe down or tap outside closes).
   - Every action that exists on PC exists on the phone: nothing hidden, only moved into More.
3. **Touch on the canvas** (phone and tablet): one finger on a design moves it (tap first to
   select); one finger on empty canvas or mat pans the view; two fingers pinch to zoom and pan;
   tap on empty space deselects; long-press on a design opens its More menu. The canvas uses
   `touch-action: none` inside the non-scrolling shell (replaces today's touch scrolling, which
   was a stopgap for the scrolling page). Handles and buttons at least 44 px on touch.
4. **PC shortcuts** (consensus): add Space + drag to pan, Ctrl+Y as redo (besides Ctrl+Shift+Z),
   Alt + drag to duplicate, and a "?" key that opens the shortcuts list. Existing: Delete,
   Ctrl+D, arrows (Shift = 1 cm), Ctrl+wheel zoom, Ctrl+A, Ctrl+S, Ctrl+V.
5. **PC top bar** grouped: File (New, Open, Save) | Undo, Redo | Zoom | film metres | Export; the
   file actions stop disappearing below 1100 px (they move into an overflow menu instead).

## Non-goals

No change to the model, Arrange, export or file formats. No new runtime dependency (pinch and
pan by hand on pointer events; Fabric stays the canvas).

## Constraints

- Desktop behaviour stays as is apart from the floating bar, the grouped top bar and the new
  shortcuts; the inspector stays on the right on PC.
- The phone shell must not break the existing phone fixes' intent: the whole sheet reachable,
  the page never jumping, the empty inspector not shown.
- Functions ≤ 100 lines, complexity ≤ 8; `mountCanvas` and `mountPanel` must not grow (new code
  in its own modules, e.g. `src/editor/action-bar.ts`, `src/editor/phone-shell.ts`,
  `src/editor/touch.ts`, `src/editor/bottom-sheet.ts`).
- Tests: unit where logic is pure (bar placement maths, gesture maths); Playwright for PC
  (floating bar appears, flips below at the top edge, hides while dragging, each action works,
  keyboard), and for phone (390×844, isMobile, hasTouch): no page scroll, bottom bar swap,
  every bottom sheet opens and closes, every PC action reachable, pinch zoom and one-finger pan
  through the DevTools protocol, tap selects, long-press opens More. Existing phone tests are
  updated to the new shell, not deleted.
- A real iPhone check by the owner after deploy (iOS Safari behaviour cannot be fully tested
  here).

## Phases

1. PC floating action bar + More menu + shortcuts + grouped top bar.
2. Phone shell: top bar, bottom bar (two states), bottom sheets, everything reachable.
3. Touch gestures on the canvas (pan, pinch, long-press), replacing touch scrolling.

Each phase: tests first, gates by exit code, screenshots at 390×844 and 1440×900 checked by eye,
CTO review, then deploy.
